# העלאת הגרסה החדשה — צ׳קליסט פשוט

כתובת המערכת: **https://argaman.vercel.app/** (כניסה: https://argaman.vercel.app/login)

עובדים לפי הסדר. כל שלב — לסמן ✅ לפני שממשיכים.

---

## 1. גיבוי

1. נכנסים ל-Supabase ← הפרויקט של ארגמן.
2. בתפריט: **Database** ← **Backups**.
3. מוודאים שיש גיבוי מהיום. אם אין — לוחצים ליצירת גיבוי (או מייצאים את הנתונים) ומחכים שיסתיים.

## 2. עדכון מסד הנתונים (SQL Editor)

**איך מריצים קובץ (אותה דרך לכל קובץ):**
1. פותחים את הקובץ ב-GitHub: https://github.com/barzaken/argaman ← בוחרים את הענף `claude/gallant-edison-tfuwan` (או `main` אחרי המיזוג) ← תיקייה `sql` ← שם הקובץ.
2. לוחצים על כפתור ההעתקה (Copy raw file) — או **Raw**, ואז Ctrl+A ו-Ctrl+C.
3. ב-Supabase: **SQL Editor** ← **New query** ← מדביקים (Ctrl+V) את **כל** הקובץ.
4. לוחצים **Run**.
5. מחכים להודעה **Success** (בדרך כלל "Success. No rows returned"). הודעה אדומה = עוצרים ושולחים צילום מסך למפתח.

**הקבצים, לפי הסדר:**
1. רק אם עוד לא הורץ בעבר: `sql/patch-2026-11-security-and-integrity.sql`
2. רק אם עוד לא הורץ בעבר: `sql/patch-2026-11-crm-users-allowlist.sql` (משתמשים קיימים נכנסים לרשימה אוטומטית)
3. `sql/patch-2026-11-documents-payments.sql` — מסמכים, תשלומים, ספקים, הוצאות, תפקידים, יומן פעולות
4. `sql/patch-2026-11-document-links.sql` — קישורים בין מסמכים ונעילה נגד הפקה כפולה ב-Morning

(מותר להריץ קובץ פעמיים — זה לא מזיק.)

## 3. בדיקה שהעדכון עבר

1. ב-Supabase: **Storage** — צריך להופיע דלי (bucket) בשם **documents**.
2. ב-**SQL Editor** ← New query ← מדביקים ← **Run**:

```sql
SELECT t AS "טבלה", to_regclass('public.' || t) IS NOT NULL AS "קיימת"
FROM unnest(ARRAY['suppliers','documents','payments','payment_allocations',
                  'expenses','order_charges','activity_log','document_links',
                  'gi_issue_requests','crm_users']) AS t;
```

3. בכל השורות בעמודה "קיימת" צריך להיות **true**. אם יש **false** — חוזרים לשלב 2 ומריצים שוב את הקובץ המתאים.

## 4. משתמשים: כל עובד עם חשבון משלו

סוכן ה-AI בוואטסאפ עובד **בשם האדם שמדבר איתו**, עם שם המשתמש והסיסמה שלו (האדם מזין אותם בקישור מאובטח — לא בצ׳אט). לכן לכל עובד צריך חשבון משלו.

**א. לוודא שאתם מנהלים.** ב-SQL Editor (להחליף את האימייל לשלכם):

```sql
SELECT u.email, c.role
FROM auth.users u
LEFT JOIN public.crm_users c ON c.user_id = u.id
WHERE u.email = 'your.email@example.com';
```

צריך לראות `admin`. אם ריק או `agent` — מריצים:

```sql
INSERT INTO public.crm_users (user_id, role)
SELECT id, 'admin' FROM auth.users WHERE email = 'your.email@example.com'
ON CONFLICT (user_id) DO UPDATE SET role = 'admin';
```

**ב. הוספת עובד חדש:**
1. ב-Supabase: **Authentication** ← **Users** ← **Add user** ← **Create new user**.
2. ממלאים אימייל וסיסמה, מסמנים **Auto Confirm User**, ולוחצים **Create user**.
3. ב-SQL Editor מריצים (עם האימייל של העובד). `'agent'` = עובד בלי הרשאת מחיקה (מומלץ לרוב הצוות), `'admin'` = מנהל:

```sql
INSERT INTO public.crm_users (user_id, role)
SELECT id, 'agent' FROM auth.users WHERE email = 'worker@example.com'
ON CONFLICT (user_id) DO UPDATE SET role = EXCLUDED.role;
```

4. בלי הפקודה הזו העובד יוכל להתחבר, אבל יראה מערכת ריקה.
5. אחר כך אפשר לשנות תפקיד בכל רגע מתוך המערכת: **הגדרות** ← **משתמשים והרשאות** (רק מנהל).

**ג. (רשות) משתמש נפרד לבוט.** אם רוצים שהבוט יעבוד גם עם משתמש משלו — יוצרים משתמש כמו בסעיף ב׳ (למשל `bot@...`) עם התפקיד `'agent'`.

**ד. כיבוי הרשמה חופשית** (אם עוד לא כובתה): **Authentication** ← **Sign In / Providers** ← לכבות **Allow new users to sign up**.

## 5. העלאת הקוד

1. ממזגים את הענף `claude/gallant-edison-tfuwan` ל-`main` ב-GitHub.
2. Vercel מעלה את הגרסה אוטומטית. מחכים שב-Vercel ← **Deployments** הגרסה האחרונה תהיה **Ready**.

## 6. חיבור Green Invoice (Morning) — קודם סביבת בדיקות

**איפה מקבלים מפתחות:**
1. נכנסים ל-Morning (Green Invoice). לבדיקות — לחשבון סביבת הבדיקות (`sandbox.d.greeninvoice.co.il`), שיש לו חשבון ומפתחות נפרדים.
2. **הגדרות** ← **כלי מפתחים** ← **מפתחות API** ← יוצרים מפתח חדש.
3. שומרים את **מזהה המפתח (ID)** ואת **הסוד (Secret)** — הסוד מוצג פעם אחת בלבד. נדרש מנוי שכולל גישת API.

**הגדרה ב-Vercel:**
1. Vercel ← הפרויקט ← **Settings** ← **Environment Variables**.
2. מוסיפים שלושה משתנים (Environment: Production):

| שם | ערך |
|---|---|
| `GREEN_INVOICE_API_KEY_ID` | מזהה המפתח |
| `GREEN_INVOICE_API_KEY_SECRET` | הסוד (לסמן Sensitive) |
| `GREEN_INVOICE_ENV` | `sandbox` |

3. **Deployments** ← על הגרסה האחרונה ⋯ ← **Redeploy** ← מחכים ל-**Ready**. (משתנים חדשים נכנסים לתוקף רק אחרי פריסה מחדש.)

## 7. בדיקות בסביבת הבדיקות (sandbox)

נכנסים למערכת כמנהל: https://argaman.vercel.app/login

**7.1 בדיקת חיבור** — **הגדרות** ← כרטיס Green Invoice ← **בדיקת חיבור**.
- [ ] כתוב **מחובר**, הסביבה **בדיקות**, **התחברות (טוקן): תקינה**.
- [ ] מופיעים **שם העסק**, **מספר חשבונית המס הבאה** ו-**שיעור מע״מ בחשבון**. (אם אחד מהם חסר — לצלם ולשלוח למפתח.)

**7.2 חשבונית מס עם הנחה ועיגול**
1. **מסמכי Morning** ← **הפקת מסמך Morning** ← סוג **חשבונית מס (305)** ← לקוח לבדיקה.
2. שורה 1: תיאור "בדיקה", כמות 1, מחיר 1000. **הוספת שורת הכנסה** ← שורה 2: תיאור "הנחה", כמות 1, מחיר **-100**.
3. לסמן **עיגול סכומים**. ללחוץ **תצוגה מקדימה**.
- [ ] הסכום ב-PDF זהה ל**סה״כ לתשלום** בטופס.
4. **הפקת חשבונית מס** ← אישור.
- [ ] הופיעה הודעה "הופק ב-Morning: חשבונית מס מס׳ …", ובמסמך שנפתח הסכום זהה לזה שב-Morning.

**7.3 קבלה בצ׳ק בלי שורות הכנסה**
1. **תשלומים** ← **רישום תשלום** ← אותו לקוח, סכום כמו החשבונית, **צ׳ק**, אסמכתא 123456 ← **שמירת תשלום**.
2. בדף התשלום ← **הפקת מסמך Morning** ← סוג **קבלה (400)**. ב**תקבולים**: למלא בנק, סניף, מספר חשבון. לא להוסיף שורות הכנסה.
3. ב**מסמכים מקושרים** לבחור את החשבונית מ-7.2 ← **הפקת קבלה** ← אישור.
- [ ] הקבלה הופקה; ב-PDF מופיעים פרטי הצ׳ק.
- [ ] ב-**חיפוש ב-Morning** החשבונית מ-7.2 מופיעה עכשיו כ**סגור**.

**7.4 חשבונית זיכוי (מנהל)**
1. בדף החשבונית מ-7.2 (במסמכים) ← **הפקת מסמך Morning** ← סוג **חשבונית זיכוי (330)**, סוג הקישור **ביטול / זיכוי המסמך**.
2. שורה: "זיכוי בדיקה", כמות 1, מחיר 100 (מספר **חיובי**) ← **תצוגה מקדימה**.
- [ ] ב-PDF הסכום מוצג כזיכוי (לא כחיוב נוסף). אם הוא נראה כחיוב — **לא להפיק**, לצלם ולשלוח למפתח.
3. להפיק ← אישור.
- [ ] המסמך הופק, ובחשבונית המקורית ב"מסמכים מקושרים" כתוב **בוטל ע״י**.

**7.5 חיפוש מסמכים ב-Morning**
1. **מסמכי Morning** ← **חיפוש ב-Morning** ← בלי סינון ← **חיפוש ב-Morning**.
- [ ] מופיעים המסמכים מהבדיקות, עם סוג, מספר, תאריך, לקוח, סטטוס וסכום.
2. לחפש לפי **מספר מסמך** של החשבונית.
- [ ] נמצא מסמך אחד.

**7.6 רשימת סיווגי הוצאות**
1. **הוצאות** ← לפתוח הוצאה (או ליצור חדשה) ← **שליחה ל-Green Invoice**.
- [ ] ברשימה **סיווג הנהלת חשבונות** מופיעים סיווגים עם שמות (לא ריקה ולא "לא נמצאו סיווגי הוצאות").

**7.7 צירוף קובץ להוצאה**
1. **מסמכים** ← **העלאת מסמך** ← סוג **חשבונית ספק**, לצרף תמונה, מספר וסכום ← **שמירת המסמך**.
2. **הצעד הבא: רישום כהוצאה** ← קטגוריה ← **שמירת הוצאה** ← **שליחה ל-Green Invoice** ← לבחור סיווג ← **שליחה** ← אישור.
- [ ] ההודעה היא "ההוצאה נשלחה ל-Green Invoice **והקובץ צורף**", וב-Morning ההוצאה מופיעה עם הקובץ.
- אם ההוצאה נשלחה אבל בלי הקובץ — לרשום ולשלוח למפתח (ייתכן שבסביבת הבדיקות כתובת ההעלאה שונה).

**7.8 שליחה במייל**
1. להפיק מסמך בדיקה (למשל הצעת מחיר 10) ולהזין ב**מיילים לשליחת המסמך** את המייל **שלכם**.
- [ ] ההודעה כוללת "(נשלח במייל)", והמייל הגיע אליכם עם קישור למסמך.

**7.9 בדיקה כללית**
- [ ] התחברות — כל המסכים נטענים.
- [ ] **מסמכים** ← העלאת תמונה ← היא מוצגת בדף המסמך.
- [ ] **רשימת חייבים** — הסכומים נראים תקינים.
- [ ] כניסה עם משתמש `agent` — אין כפתורי מחיקה.

## 8. מעבר לחשבון האמיתי (ייצור)

רק אחרי שכל שלב 7 עבר:
1. ב-Morning **האמיתי** (`app.greeninvoice.co.il`): **הגדרות** ← **כלי מפתחים** ← **מפתחות API** ← מפתח חדש.
2. Vercel ← **Settings** ← **Environment Variables**: להחליף את `GREEN_INVOICE_API_KEY_ID` ו-`GREEN_INVOICE_API_KEY_SECRET` במפתח האמיתי, ואת `GREEN_INVOICE_ENV` ל-`production`.
3. **Deployments** ← ⋯ ← **Redeploy** ← מחכים ל-**Ready**.
4. **הגדרות** ← **בדיקת חיבור**: צריך להופיע **מחובר** והסביבה **ייצור**, עם שם העסק האמיתי.
5. מכאן כל מסמך שמופק הוא מסמך חשבונאי אמיתי ואי אפשר למחוק אותו.
